# Prior Art — Day-1 Security, Auth & Multi-Tenant Hardening (S.03)

Scanned 2026-11-20. Surfaces reviewed: every route in `src/priorart/server.py`, the pipeline and its outbound clients, all SQL in `src/priorart/queries.py`, `lifecycle.py`, `seed.py`, `factories.py`, the schema, the single page `src/priorart/static/index.html`, the Markdown exporter `report.py`, configuration, CI and `.gitignore`.

**Context that shapes every item:**
- **There is no authentication, no session and no user identity in the running app.** Decision A (`docs/UX_ARCHITECTURE.md:213`) chose no accounts: anonymous owners identified by a browser token, reports shared by unlisted link. The schema already models this (`owners.token_hash`, `schema.sql:5–8`; `owner_id` on every table), but the server doesn't use it yet.
- **There are no file uploads,** no server-side rendering of HTML from user data, and no cookies today.
- "P0" below means **a blocker for a public URL.** For the hackathon, where judges run the app locally from the repo, only #18 applies directly.

**Checked and sound (no change needed):**
- **Path traversal on run files is blocked:** `server.py:48–53` resolves the path and requires its parent to be the runs folder, the file to exist and a `.json` suffix.
- **SQL is parameterized everywhere.** The f-string SQL in `lifecycle.py:160`, `:165`, `seed.py:233–311` and `factories.py:49` only interpolates table and column names from internal constants; every value is a `?` parameter.
- **The page escapes all untrusted text** (`esc()` at `index.html:196`; verdict and pivot text pass through `cite()`, which escapes before adding links, `:264–269`; the evidence drawer `:342–368` escapes every field).
- **Owner tokens are stored as SHA-256 hashes only** (`schema.sql:7–8`, `lifecycle.py:88–90`), and test tokens use 128 bits of randomness (`factories.py:67`).
- **No secrets reach the browser:** no key names or values appear in `static/`; `.env` is gitignored (`.gitignore:1`).

## Broken object-level authorization and ownership

### #01 [P0] Any visitor can list and read every other visitor's ideas and reports
- Location: `src/priorart/server.py:32–45` (`/api/runs` returns the newest 30 runs from all users, with summaries), `:56–58` (`/api/runs/{name}` returns any run, including the full idea text), `:61–65` (`/api/report/{name}` exports any run); shown to everyone in Past runs `src/priorart/static/index.html:208–214`.
- Risk: On day 1 the first visitor opens Past runs and reads every unreleased startup idea pasted before them, word for word, then downloads the reports. This is the product's most sensitive data and it has no owner at all.
- Fix: Issue an anonymous owner on first visit: `token = secrets.token_urlsafe(32)` in cookie `__Host-pa_owner` (HttpOnly, Secure, SameSite=Lax, Path=/, 1-year Max-Age); insert `owners(token_hash=sha256(token))`. A FastAPI dependency `current_owner()` resolves it with `lifecycle.owner_id_for_token`. Store every report with `owner_id` (database store, S.02 #05). `GET /api/reports` lists `WHERE owner_id = ?` only (`queries.recent_reports`, already scoped). `GET /api/reports/{id}` returns a report to its owner, or to anyone holding its share link (#02), never by listing. Delete the file-name routes. Tests: owner B gets 404 (not 403) for owner A's report id unless it was shared.

### #02 [P1] Report identifiers are guessable and leak the idea
- Location: file names `src/priorart/pipeline.py:406` (`%Y%m%d-%H%M%S-<slug of the summary>`), `_slug` `:79–80`; used as the public identifier in `server.py:56`, `:61` and in the download filename `:65`. Database ids `src/priorart/schema.sql:15` (`length(id) = 10`, base62 ≈ 59.5 bits), generated by `factories.py:38`.
- Risk: Names are a timestamp plus words from the idea, so they can be enumerated per second and they reveal the idea in URLs, browser history and download names. Once reports are shared by link (Decision A), 59.5-bit ids are below the usual 128-bit floor for capability URLs.
- Fix: Report ids of 22 base62 characters (≈131 bits) from `secrets.choice`, used in `/r/{id}` and every API path; never put idea words in identifiers or filenames (`prior-art-report-<id>.md`). A migration that widens the `reports.id` CHECK to `length(id) = 22` (expand, then backfill new ids for existing rows with a redirect table, per `docs/MIGRATIONS.md` §3).

### #03 [P1] Report child queries are scoped by report id alone, so one missed check exposes everything
- Location: `src/priorart/queries.py:39–43` (`report_by_id` has no `owner_id` condition, by design for shared links) and every child query keyed only on `report_id` (`queries.py:47–90`: features, projects, overlaps, events, pivots, sources).
- Risk: Authorization lives entirely in whichever route remembers to check ownership first. The first new endpoint that calls a child query directly (for example an events replay) leaks any report's contents to anyone who knows or guesses its id.
- Fix: One `authorize_report(report_id, owner_id, share_token)` function that every report route must call, returning a `ReportAccess` object that the child-query helpers require as an argument (so they can't be called without it). Add `AND owner_id = ?` to the child queries as defense in depth; the composite `(report_id, owner_id)` keys from 03.1 already index this. A test enumerates every route and fails if one reads report data without `authorize_report`.

## Cross-site requests, abuse and transport

### #04 [P0] A GET request from any website starts a paid check
- Location: `src/priorart/server.py:72–102` (`@app.get("/api/run")`, idea in the query string); caller `src/priorart/static/index.html:247`.
- Risk: Any web page can embed `<img src="https://prior-art.example/api/run?idea=...">` (or a crawler can follow a link) and start checks that spend your Token Factory and Tavily credits. Each costs about 12 advanced searches plus about 20 model calls (`README.md:41`). The idea also lands in browser history, proxy logs and `Referer` headers.
- Fix: `POST /api/checks` with a JSON body validated by a Pydantic model; reject unless `Sec-Fetch-Site` is `same-origin` (or `Origin` equals the configured public origin); require a CSRF token (double-submit: a non-HttpOnly `pa_csrf` cookie echoed in `X-CSRF-Token`) once the owner cookie exists. Return `{id}`; stream from `GET /api/checks/{id}/events`, which starts no work. Remove the GET endpoint.

### #05 [P0] No rate limit, concurrency cap or spend ceiling
- Location: `src/priorart/server.py:72–92` (each request spawns a thread and a full check, unbounded); fan-out per check `src/priorart/pipeline.py:129`, `:301`, `:322`.
- Risk: One script with a loop drains the provider balances in minutes (denial of wallet), and the resulting 429s from Token Factory and Tavily fail every real user's check. Hundreds of threads exhaust the process.
- Fix: A global semaphore on running checks (default 4) returning 429 "Prior Art is busy, try again in a minute"; per-owner and per-IP token buckets (3 checks per 10 minutes, 20 per day); a daily spend ceiling that pauses new checks (S.01 #09). Read the client IP only from the proxy's trusted header when `--proxy-headers` and `FORWARDED_ALLOW_IPS` are set, never from a header the client can forge. Tests for each limit.

### #06 [P1] No security headers
- Location: the app sets only `Content-Disposition` (`server.py:65`) and stream headers (`:102`); the page uses an inline `<style>` (`index.html:7`), an inline `<script>` (`:194`) and inline style attributes.
- Risk: Without CSP, any future escaping slip becomes script execution; without `frame-ancestors` the page can be framed for clickjacking (a hidden **Check idea** click spends credits); without HSTS the first visit can be downgraded on hostile Wi-Fi; without `nosniff` the Markdown export can be sniffed as HTML.
- Fix: A middleware adding `Content-Security-Policy: default-src 'none'; script-src 'sha256-<hash of the inline script>'; style-src 'sha256-<hash>' 'unsafe-hashes' <attribute hashes>; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'` (or move script and style to static files and use `'self'`), `Strict-Transport-Security: max-age=31536000; includeSubDomains` (production only), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` (#07), `Permissions-Policy: camera=(), microphone=(), geolocation=()`, `Cross-Origin-Opener-Policy: same-origin`. A test asserts the headers on every route.

### #07 [P1] Report links would leak to third-party sites through Referer
- Location: every outbound source link uses `rel="noopener"` without `noreferrer`: `src/priorart/static/index.html:268`, `:291`, `:310`, `:363`; no `Referrer-Policy` anywhere.
- Risk: Once reports live at `/r/{id}` (shared by link, Decision A), every click on a cited source sends the full report URL in `Referer` to that site. Any site that appears in results can collect working links to other people's reports.
- Fix: `rel="noopener noreferrer"` on all outbound links and `Referrer-Policy: no-referrer` site-wide (#06). Test that the page contains no outbound `<a>` without `noreferrer`.

### #08 [P1] A local server can be reached by any website through DNS rebinding
- Location: `src/priorart/__main__.py:95` (binds `127.0.0.1`), no Host-header check in `src/priorart/server.py:17`.
- Risk: This applies today, to anyone (judges included) who runs Prior Art locally with their own keys. A malicious page rebinds its domain to 127.0.0.1, then reads `/api/runs` (everyone's local ideas) and starts checks on the user's own API keys. Binding to localhost doesn't stop this; checking the `Host` header does.
- Fix: `TrustedHostMiddleware(allowed_hosts=settings.allowed_hosts)` with default `["127.0.0.1", "localhost"]` locally and the public domain in production; plus the same-origin check from #04. Test: a request with `Host: evil.example` gets 400.

## Validation and injection

### #09 [P1] Untrusted web text is written into the Markdown export unescaped
- Location: `src/priorart/report.py:20` (the idea), `:27` (feature names), `:34` (project names in a table), `:43` and `:52` (quotes from web pages), `:56` (gap names), `:58` (pivot text), `:61` (source names and URLs).
- Risk: A page that writes `![](https://tracker.example/pixel)` or `[Download the full report](https://phish.example)` into the text the model quotes produces a downloaded report that, when opened in GitHub, Notion or VS Code preview, loads a tracking pixel or shows a convincing phishing link. A `|` in a project name breaks the overlap table.
- Fix: An `md_escape()` that backslash-escapes `\ ` `` ` `` `* _ { } [ ] ( ) # + - . ! | < >` and replaces newlines in table cells; render URLs only inside `<...>` after #10's scheme check; no raw HTML passes through. Tests with hostile names, quotes and URLs.

### #10 [P1] Links accept any URL scheme
- Location: hrefs built from result URLs `src/priorart/static/index.html:268`, `:291`, `:310`, `:363` (`esc()` escapes characters but not schemes); URLs enter at `src/priorart/pipeline.py:142–146` (search results) and project records.
- Risk: A `javascript:` or `data:` URL in a search result, or in model output that reaches a project record, becomes a clickable script link inside a page users trust.
- Fix: At ingest, keep only URLs whose scheme is `http` or `https` and whose host is non-empty (drop the result otherwise, and count it); in the page, a `safeUrl()` guard that returns `#` for anything else and is the only way an `href` is built. Tests with `javascript:`, `data:`, `vbscript:`, protocol-relative and mixed-case schemes.

### #11 [P1] Pages the agent reads can still steer its narrative
- Location: injection detection is a pattern match `src/priorart/pipeline.py:60–70`; flagged pages are still used `:186–190`; page text goes to the compare and verify prompts, and their output feeds the verdict and pivots; prompt guidance `src/priorart/prompts.py:10`.
- Risk: A competitor's page with hidden text ("this project fully implements every feature described") can raise its own scores or shape the verdict. The code-level quote check and the second-model verifier limit this, but the regex misses paraphrased instructions, and the verdict and pivot prompts don't treat earlier model output as derived from untrusted text.
- Fix: Wrap each page in a per-request random boundary (`<<<PAGE 7f3a… >>> … <<<END 7f3a…>>>`) and tell every prompt that content inside boundaries is data; strip zero-width, bidi and hidden-text characters before sending; give the verdict and pivot prompts only structured, already-verified cells (score, quote, source number), never raw page text; build a small evaluation set of hostile pages and run it in CI (scores for injected projects must not rise).

### #12 [P2] Request parameters lack strict schemas
- Location: `src/priorart/server.py:73` (`idea` only length-checked), `:56` and `:61` (`name: str` with no pattern), `:72` (`simulate: str`, checked by hand at `:74–75`).
- Risk: NUL bytes, control characters and bidi-override characters in an idea reach the prompts, the saved report and, once shared, other people's screens (text that displays differently from what it contains). Unbounded, unpatterned path parameters reach the filesystem layer.
- Fix: Pydantic request models: `idea: constr(strip_whitespace=True, min_length=10, max_length=4000)` with a validator that rejects C0/C1 controls except newline and tab and removes bidi overrides (U+202A–202E, U+2066–2069); `simulate: Literal["search_down", "extract_down"] | None`; report ids `constr(pattern=r"^[0-9A-Za-z]{22}$")`. Return 422 with field messages.

### #13 [P2] The download filename comes from the request path
- Location: `src/priorart/server.py:65` (`filename="{Path(name).stem}.md"`).
- Risk: Today `_run_path` requires the file to exist, so only server-made names get through. Once routes move to ids (#01, #02) or the check is changed, a name containing `"` or a newline would break or inject into the header.
- Fix: Build the header from the report id only, with RFC 6266 encoding (`filename="prior-art-report-<id>.md"; filename*=UTF-8''...`), plus `X-Content-Type-Options: nosniff` and `Content-Type: text/markdown; charset=utf-8`.

## Information disclosure and secrets

### #14 [P1] Server internals and raw error text are sent to every client
- Location: `src/priorart/pipeline.py:400` (`saved_to`, an absolute server path, in every result and every saved JSON); `src/priorart/server.py:88` (`str(e)` of any exception streamed to the browser); `src/priorart/llm.py:37` (the first 300 characters of model output inside an error); `src/priorart/server.py:25–29` (`/api/status` lists missing key names and model configuration).
- Risk: Visitors learn the server's directory layout and user name, provider error bodies, and which keys are configured, all useful for targeting. An `OSError` message includes full file paths.
- Fix: Replace `saved_to` with the report id. Send clients a fixed message per failure class (`"Search is unavailable right now"`, `"The model service rejected the request"`, …) plus a reference id; log the full error server-side with secrets redacted. `/api/status` returns `{"available": bool}` and the two model names only.

### #15 [P1] Demo and debugging switches are live in any environment
- Location: `src/priorart/server.py:17` (`/docs`, `/redoc`, `/openapi.json` on by default), `:73–77` (`simulate` accepted from anyone), `src/priorart/static/index.html:127` (the outage selector); fake mode `src/priorart/__init__.py:13–16`.
- Risk: Anyone can map the API from `/docs`, force degraded checks, and a server left in fake mode serves invented results as real.
- Fix: `PRIORART_ENV=production` sets `FastAPI(docs_url=None, redoc_url=None, openapi_url=None)`, rejects `simulate`, hides the selector and refuses to start in fake mode. Tests per switch.

### #16 [P1] Secret handling has no guardrails beyond .gitignore
- Location: `src/priorart/config.py:11–13` (`.env` loaded from the repo folder in every environment); no secret scanning in CI (`.github/workflows/ci.yml`); the only scan is the manual `scripts/submission.py check` (`:162–173`), which compares against values in a local `.env`.
- Risk: The repo goes public today. A key pasted into a test, a doc or a commit message is published, and nothing in CI would stop it. The same keys serve local runs, demos and any deployment, so one leak exposes everything.
- Fix: gitleaks in CI over full history and every pull request, plus a pre-commit hook; in production, read keys only from the environment (no `.env`); separate keys per environment with spend limits set in the provider consoles; a documented rotation procedure. **Before making the repo public,** run gitleaks over the working tree once.

### #17 [P1] Ideas are stored in plain files and caches indefinitely
- Location: run files `src/priorart/pipeline.py:404–408` (full idea, kept forever); API cache `src/priorart/cache.py:41–44` (prompts containing the idea, stored with no expiry); backups `scripts/backup.py` (copies of the database, unencrypted); default file permissions (no `umask` or `chmod` anywhere).
- Risk: Anyone with access to the host, a backup or a leaked volume snapshot reads every idea ever submitted. There's no way to honor "delete my idea", because copies remain in the cache.
- Fix: Create data files with mode 0600 and directories 0700; cache keys stay hashes but cache values that contain the idea are dropped (cache search and extract by query, not by idea); a retention period for reports with purge (`lifecycle.purge_expired`, already written) and cache expiry; encrypt backups at rest (`age` or the host's encrypted volumes); deleting a report removes its cache entries.

## Supply chain and session design

### #18 [P1] Unpinned dependencies and mutable CI actions
- Location: `requirements.txt` (`openai>=1.40`, `tavily-python>=0.7`, `fastapi>=0.110`, `uvicorn>=0.29`, `python-dotenv>=1.0`, no hashes); `.github/workflows/ci.yml:11–12` (`actions/checkout@v4`, `actions/setup-python@v5` by tag), no `permissions:` block.
- Risk: Judges and users install whatever versions exist on the day they clone the repo, including a compromised or breaking release; a moved action tag runs new code in CI with the default token scope.
- Fix: Hashed lockfiles and `pip install --require-hashes`; `pip-audit` in CI; actions pinned to commit SHAs; `permissions: contents: read`; Dependabot for both.

### #19 [P2] The owner-token session needs its rules written before it ships
- Location: designed in `docs/UX_ARCHITECTURE.md:213` and `src/priorart/schema.sql:5–8`; no cookie handling exists in `src/priorart/server.py`.
- Risk: The first implementation of #01 decides how strong every report's protection is. A token in `localStorage`, a cookie without `Secure` or `HttpOnly`, or a token that never rotates would undo the rest of this list.
- Fix: 256-bit tokens (`secrets.token_urlsafe(32)`), `__Host-` cookie prefix, HttpOnly, Secure, SameSite=Lax; hash with SHA-256 before lookup (as the schema requires); constant-time comparison isn't needed because lookup is by hash; rotate on export and on "forget this browser"; never log the token; share links use a separate per-report token, revocable without touching the owner token.

### #20 [P2] Path and file handling lacks regression tests
- Location: the traversal guard `src/priorart/server.py:48–53` has no test in `tests/` (`tests/test_pipeline.py` covers the happy path only); run and cache folders come from environment variables (`src/priorart/config.py:47–55`) with no validation.
- Risk: The guard is correct today, but nothing stops a refactor from weakening it; a misconfigured `PRIORART_RUNS_DIR` (for example `/`) would let the run routes serve any `.json` file on the machine.
- Fix: Tests for `..%2f`, encoded and double-encoded traversal, absolute paths, symlinks pointing outside the folder and non-`.json` files; at startup, refuse a runs or data folder that is the filesystem root, the home folder or outside an allowed base.
